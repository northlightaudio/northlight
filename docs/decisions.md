# Decisions

Why Northlight is built the way it is. Each entry records a choice, the date it was
made and the reason, so a later change can tell what it is trading away. The log is
grouped by area; an entry that replaced an earlier choice says so.

For how the pieces fit together see [architecture.md](architecture.md).

## Foundations

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | Windows first; a platform seam kept for a later port | ASIO and VST3 hosting are the hard requirements and both are Windows-first. The device layer, plugin window embedding and file dialogs sit behind interfaces so macOS and Linux remain possible. |
| 2026-10-19 | VST3 and CLAP; no VST2, AAX or AU | Steinberg no longer licenses VST2 to new hosts. CLAP is open (MIT) and cheap to add beside VST3. |
| 2026-10-19 | MIDI and instruments in the first version | With the bundled instruments the application is useful on its own. |
| 2026-10-21 | Licensed under the GNU AGPLv3 | It matches JUCE's open licence and takes the ASIO SDK under its GPLv3 option (GPLv3 section 13 allows the combination); every other dependency is permissive. See LICENSE and THIRD_PARTY_NOTICES.md. |
| 2026-10-21 | Renamed from Aural to Northlight | A name of its own for the public release. Settings and folders from the old name migrate on first start. |
| 2026-10-21 | Signalsmith Stretch for time-stretch | MIT licensed and very good; Rubber Band would have cost a licence. |
| 2026-10-23 | ASIO from the header bundled with JUCE, on in every build | JUCE 8.0.11 bundles the ASIO SDK header under the SDK's GPLv3 option, the same option the AGPLv3 decision relies on. Building no longer needs Steinberg's SDK, distributed builds include ASIO, and CI compiles the ASIO code. A local SDK can still replace the header. |

## Log

### Platform and build

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | C++20 and JUCE 8, not Rust | VST3 hosting and plugin-window embedding are mature in JUCE and immature in Rust. |
| 2026-10-22 | Unattended captures while the machine is in use run with no native window (`--offscreen`), not on another virtual desktop | A window on another desktop switched the user there: Windows follows activation to a window's desktop, and JUCE activates windows as it makes them (a window created on the desktop takes the foreground, `setUsingNativeTitleBar` brings it to the front) and on `grabKeyboardFocus`. Without a native window nothing can be activated; the windows still lay out, tick and paint (four times a second, so parts that load on their first paint are ready for the capture). |
| 2026-10-19 | Own engine rather than Tracktion Engine | Licensing freedom and control of the threading and data model. |
| 2026-10-19 | Dependencies via `FetchContent`, no vcpkg yet | Nothing yet needs a package with a real build step. nlohmann::json is header-only and comes the same way. |
| 2026-10-19 | JUCE modules compiled once into `northlight_juce` and re-exported | JUCE modules add their sources to every consumer, so several consumers would give duplicate symbols. One target also gives every consumer the same module settings. |
| 2026-10-19 | The real-time allocation check overrides `operator new` in an OBJECT library | A static library's override can be discarded by the linker; OBJECT library objects are always linked. |

### Engine and real time

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | Timeline positions are samples at the project rate, not beats | Sample-accurate placement and recording with no rounding. Bars, beats and tempo are a view of the timeline through the tempo map. |
| 2026-10-19 | Snapshots are retired by epoch, not through a real-time garbage queue | The real-time thread advertises the epoch it uses and the controller frees older snapshots, so the real-time thread never touches a queue or free list. |
| 2026-10-19 | Per-track buffers live in the snapshot, not a global pool | The snapshot already knows every track and is built off the real-time thread, so no pool manager or real-time bookkeeping is needed. Render calls are capped at 8192 samples and larger device blocks are split. |
| 2026-10-19 | Workers woken by a counting semaphore; the callback spins for completion | A semaphore release is the cheapest non-blocking wake on Windows, and the spin is bounded by one track's render. |
| 2026-10-19 | Worker pool batch state packed into one atomic | Separate index and count fields let a late worker run a job from one batch against the next batch's context. One 64-bit `fetch_add` keeps them inseparable. |
| 2026-10-19 | Tracks render in parallel; buses sum on the callback thread | Buses are few and serial by dependency anyway, so parallel tracks capture the benefit without a dependency-aware scheduler. |
| 2026-10-19 | Callback load is a histogram of deadline fractions | Percentiles need no sorting or allocation, and a fraction of the deadline means the same at any buffer size. |
| 2026-10-19 | Live values travel as targets the renderer ramps to; structural edits recompile | A fader move must glide, not step, and must not rebuild the graph on every mouse move. Per-channel state that outlives snapshots carries this, and automation too. |
| 2026-10-19 | Insert parameters are atomics on a persistent instance, not part of the snapshot | Recreating a processor on every edit would reset its state and click. The snapshot stays immutable. |
| 2026-10-19 | Meters are peak-hold plus last-block RMS in atomics | The UI cannot miss a peak between frames and applies its own ballistics, with no queue. |
| 2026-10-20 | Editor feedback is a ring of atomics per processor, polled by the UI | Preallocated and non-blocking, with no queue per display; a display tolerates the rare torn frame. |
| 2026-10-19 | Own Hermite resampler instead of `juce::LagrangeInterpolator` | JUCE's interpolator carries a lookback delay and sequential state, which misaligned media and complicated seeks. A stateless resampler at exact positions is sample-aligned. |
| 2026-10-22 | Render workers join MMCSS "Pro Audio"; the disk thread runs at `THREAD_PRIORITY_HIGHEST` | Windows boosts busy normal threads as high as time-critical, so a compile could tie with a worker and make the whole block late, whatever the buffer size. MMCSS puts the workers above that range. The disk thread only needs to beat normal work, and staying below the workers keeps file reads from taking a core from rendering. The driver's callback thread is left as the driver set it. |
| 2026-10-22 | Disk dropouts are starvations, not every underrun | Every locate plays a little silence while the window rebuilds, so counting all underruns would report a dropout on each seek. An underrun only counts when the window had caught up, and only once per gap. |
| 2026-10-19 | Loops shorter than 64 samples are refused | Each loop pass in a block costs a render span and a worker wake; very short loops have no musical use. |
| 2026-10-25 | Fade curves are a rational shape, x / (x + k(1 - x)), with k worked out when the snapshot is built | One division per faded sample on the audio thread instead of a pow, exactly linear at k = 1 so existing fades and their constant-sum crossfades are unchanged, and one curve family from slow through linear to fast. |
| 2026-10-25 | A muted clip is left out of the snapshot | Clip mute recompiles the snapshot like any structural edit, so the renderer gains no state and the audio thread no per-clip check. |

### Audio devices and media

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | Device changes go through `AudioDeviceManager::initialise` with a `DEVICESETUP` element | The other route opens the type's default device first and then the chosen one. The XML path applies everything in one open. |
| 2026-10-19 | Device rate vs project rate: empty projects follow the device, others warn | Silently resampling a whole project on a device change would hide a real problem. |
| 2026-10-19 | Files under 30 s load into memory; longer ones stream | Short clips are the common case and avoid disk latency; streaming keeps project size unbounded by RAM. |
| 2026-10-19 | One streaming window per clip, not per file | Two clips of one file would make a shared window seek back and forth and play silence. Windows are cached by clip id so edits do not reset them. |
| 2026-10-19 | The streaming window is guarded by position, with a grace period on seeks | One reader and one writer do not need a full lock-free ring; a guard distance and a short quiet period after a seek give the same safety. |
| 2026-10-19 | Peaks are mipmapped, built at the project rate and cached beside the media | Every zoom level reads a few bins per pixel, peaks share the clips' units, and a project opened from another folder still finds them. |

### Latency calibration and recording

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | Calibration uses a short windowed chirp found by cross-correlation | Impulses are smeared by converter filters and lost in noise; a chirp's correlation peak is one sample wide. Matching on magnitude tolerates polarity-inverting cables. |
| 2026-10-19 | Measured latency is stored with the device, rate and buffer size | Round trip changes with all three, and a stale figure silently misplaces recordings. |
| 2026-10-19 | Recordings are placed by calibration when it matches, else by reported latency | The measurement is the truth when it exists; the driver's figures keep placement roughly right otherwise. |
| 2026-10-19 | Recordings are 32-bit float mono WAV, one file per input | Float matches the engine and never clips; one file per input keeps placement and recovery simple. |
| 2026-10-22 | Stereo inputs are named buses of two device channels, as in Cubase, defined per device on this machine; tracks store the name | The hardware belongs to the machine, so a bus set up once serves every project, and a project moved to another machine shows its missing bus by name instead of silently recording the wrong channels. Single channels stay selectable, so mono recording needs no setup. A stereo input records one two-channel file, keeping one file per track input. |
| 2026-10-19 | The record session lives outside the snapshot | Editing during a take swaps snapshots, which must not disturb the rings or restart capture. |
| 2026-10-19 | Count-in and punch are handled by segmenting the block on the real-time thread | Acting on block boundaries would be up to one buffer late; segmenting is sample-accurate at any buffer size. |
| 2026-10-19 | One region serves both loop and punch | Two overlapping regions are hard to read and rarely differ; the toggles decide what the region means. |
| 2026-10-19 | Takes are split by the writer at marks from the audio thread, one file per pass | The audio thread must not open files, so it only pushes a sample count. One file per take keeps every take a plain clip. |
| 2026-10-19 | Dropped record blocks become silence, not a shorter file | A shorter file would shift every later sample and take boundary. |
| 2026-10-19 | Crash safety by periodic header rewrite plus repair from file size | The standard approach: a valid file at every second boundary and the tail recovered from the file size. |
| 2026-10-19 | A JSON sidecar per input, written before capture | After a crash only the sidecar knows the track, start, loop and latency, so recovery can place the take. |
| 2026-10-19 | Crash recovery asks before importing | Silently adding tracks to whatever project opens next would surprise. Declined takes are set aside, not deleted. |

### Mixing and routing

| Date | Decision | Why |
|---|---|---|
| 2026-10-22 | The master is a channel with a fixed id, and its inserts run before its fader | Every insert command, plugin window and the instance cache already work on a channel id, so the master joins them instead of growing a parallel set. Pre-fader keeps the master's chain like every other channel's and lets the fader trim the result. |
| 2026-10-22 | Master inserts take no sidechain key | Everything has been summed when they run; a key from a track would have to be held back by the whole graph to line up, and keying the mix bus is rare. |
| 2026-10-22 | The glue compressor shows a dynamics ribbon, not a transfer curve | What a bus compressor does to a mix is change the distance between its body and its peaks: a fast attack narrows it, a slow one keeps the transients and lowers the body. The ribbon (RMS to peak, in and out) and the crest factor show that directly; the curve of a 2:1 soft knee says little. |
| 2026-10-19 | Tracks and buses share one Channel type and one set of fader commands | Their fader sections, routing and sends are identical, so undo stays uniform and the mixer draws both with one strip. |
| 2026-10-19 | Solo-in-place propagates both up and down the routing | Soloing a bus plays what feeds it, and soloing a track keeps its bus and the master alive. Resolving this at compile keeps the real-time path a flag check. |
| 2026-10-19 | Routing cycles are refused at the command layer | Silently rewiring a cycle would show one graph and play another. |
| 2026-10-19 | Fader groups are commands over channel values, not engine state | The snapshot is unchanged and undo is exact. Relative moves keep the members' balance. |
| 2026-10-19 | Delay compensation per graph edge, solved at compile, lines cached across compiles | Edges handle a source feeding destinations with different needs. Solving at compile keeps the real-time path a fixed delay, and caching lines makes recompiles inaudible. |
| 2026-10-19 | Insert chains are stereo pairs | Channels are stereo, so every plugin gets a stereo main bus, which keeps hosting simple and correct for effects. |
| 2026-10-19 | Sidechain keys are pre-fader by default, can tap post-fader, and are delay compensated; keyed tracks render in dependency levels (post-fader option 2026-10-20) | A keyed track must see its source finished in the same block; levels keep everything unkeyed parallel. Post-fader keys follow level rides. A late key is left as is rather than adding latency, and bus sources for track inserts are not offered. |
| 2026-10-20 | The channel strip is stored as inserts in a second list, not a new model type | Modules need exactly what an insert has, so every insert command, undo, the instance cache and live values work on them unchanged. |
| 2026-10-20 | Strip modules that are off are compiled as bypassed inserts | Switching one is a live value with no recompile and no click. |
| 2026-10-20 | One compressor for inserts and the strip: the strip's, keyed | Two had drifted apart and needed every fix twice. Insert compressors in older projects sound somewhat different. |
| 2026-10-20 | The strip limiter has no lookahead; the insert limiter does | A strip is on every channel and must not add latency or re-solve delay compensation when switched. The insert limiter keeps lookahead for mastering (added once delay compensation landed). |
| 2026-10-19 | Fades are linear | Linear fades sum to constant level for correlated material, the common case of a take split and rejoined. |
| 2026-10-26 | Hardware outputs are a pair index in callback order, and fall back to the channel's bus where the device lacks the pair (offline too) | Inputs are named by callback order already; a project moved to a two-output machine, or exported, still plays every channel instead of dropping some silently. The renderer keeps a buffer per pair (32 at most) allocated at prepare, so the callback never allocates. |
| 2026-10-26 | A send's mute ramps its live level to zero instead of dropping the edge | Muting stays a live value with no recompile or click, and the edge's delay line keeps running, so unmuting never replays stale audio. |
| 2026-10-26 | Exclusive solo is Ctrl+click on S, and solo safe a per-channel flag in the strip's menu | Ctrl is the modifier for "do it differently" on a click elsewhere (toggle selection); Alt already breaks a fader group's link. Solo safe resolved at compile keeps the real-time path a flag check. |
| 2026-10-26 | No multi-strip selection yet | The selection is one channel shared by every view; selecting several strips would need the arrange view's track selection to become a set first. Fader groups cover moving several faders together. |
| 2026-10-26 | A mixer strip reads pan and toggles above the fader, as the spec draws it | The code had the fader straight after the sends; the spec's order is a console's, keeps M/S/R by the pan rather than under the fader, and gives the master more room for its inserts when it lines up with the channels' fader band. |
| 2026-10-26 | A short strip's "3 inserts" opens a list on click, not a pop-over on hover | A hover pop-over over a strip's middle covers the fader the pointer is often on its way to; a click is deliberate and the list is the slots' own menus. |

### Plugins

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | Built-in processors live in `src/plugins` behind the engine's insert interface | The engine must not depend on any processor; hosted plugins implement the same interface and the app injects the factory. |
| 2026-10-19 | CLAP hosted against the C ABI, VST3 through JUCE, both behind one insert interface | JUCE does not host CLAP. Thread-check answers must be truthful because plugins assert on them. |
| 2026-10-19 | Plugin scanning runs in a separate executable, one file per process | A plugin that crashes or hangs during a scan must not take the DAW with it; the file is blocklisted with the reason. |
| 2026-10-19 | Hosted plugins own their state and parameters | State is an opaque blob saved and restored, as in every host. The model's parameter list reaches the plugin only when a command touches it; pushing it on every compile reverted presets loaded from the plugin's own menu. |
| 2026-10-25 | Orbit's tape is a Jiles-Atherton hysteresis model, not a static curve | The strip saturation, Patina's Heat and the tape echo's record path are memoryless curves; what makes tape sound like tape is the magnetisation lagging the field (soft, level-dependent compression, mostly odd harmonics) and the record EQ driving the highs into it first. The model costs a second-order Runge-Kutta step per sample at about 192 kHz; bias moves its reversible share (calibrated about 0.95, which keeps quiet passages clean as real biased tape is). |
| 2026-10-25 | Orbit's meters read each channel's rectified average, not its peaks | A VU responds to the average; reading frame peaks (even taken down to a sine's rms) put music's crest, 10 to 15 dB over its average, on the needle, so ordinary levels pinned it. The processor runs each channel at the chosen point through a VU's movement (two equal 45 ms lags, 99% of a step in 300 ms), scaled so a sine reads its rms, and the card shows the newest reading: taking the loudest short average each tick, then adding the movement, still rode the drum hits. |
| 2026-10-25 | Orbit reports 1.5 ms of latency and delays its dry signal to match | The flutter's wander needs a delay to swing about; without a fixed one, a partial Mix would comb. The oversampler's round trip is measured at prepare and taken off the tape's line, so dry and wet line up. |
| 2026-10-22 | Pulsar models the TR-808's circuits rather than generic drum recipes | A big pitch sweep, a DC click and filters set as fractions of the sample rate made a laser-like kick and pads that changed with the rate. The 808's own structure (a resonator with a gentle drop, two snare modes, retriggered clap bursts, six squares through band and high passes) is what people expect a drum synth to sound like. Filters in hertz, noise scaled to the rate and an 18 kHz top keep a pad the same at any sample rate. |
| 2026-10-19 | A CLAP restart creates a fresh instance through the next snapshot, never a deactivation in place | The real-time thread may be inside `process()` at any moment; recreating with state carried over needs no real-time handshake. |
| 2026-10-26 | A crashed plugin reloads from the model's state, and the crashed instance is never destroyed | After a crash the plugin's memory may be damaged, so its live state and its destructor are not trusted; the model keeps the state from the last save or capture. Leaking one instance per crash is cheaper than a second crash on teardown. Only processing is guarded; editor and state calls on the message thread are not (guarding them needs per-call SEH around JUCE and CLAP calls with no safe recovery from a half-built window). |
| 2026-10-26 | A hosted preset load is a SetPluginState step with the plugin's state before and after | Programs and preset files change state the host does not see as parameters; the state blob is the only thing that brings it back exactly. The first apply records only, so the plugin is not reloaded with what it already has. |
| 2026-10-26 | Windows reopen with a project from a flag written at save | Opening windows is not an edit, so no command or undo step records it; the save already captures plugin state, and the flag rides along. |

### Built-in effects

| Date | Decision | Why |
|---|---|---|
| 2026-10-23 | Patina's Age maps an amount `a` to `a·2t` below the middle and `a + (1-a)·a·(2t-1)` above it | One control must take every stage from untouched to ruined without flattening the balance the user set: a stage set lightly stays the lightest, and a stage at zero stays at zero |
| 2026-10-23 | Patina's stages fade 10 ms out and in around a switch or a change of choice, with the stage reset in between | A new curve, space, machine or source mid-note would otherwise click or carry an old tail; a fade is inaudible and keeps the stages simple |
| 2026-10-23 | Patina's Drift delays the sound by its own wobble and does not report latency | The mean delay moves with the depth and rate (up to about 30 ms at the slowest, deepest settings); a fixed reported latency would have to be the worst case all the time. A tape machine has the same offset |
| 2026-10-23 | Patina's card reads a telemetry block of its own (`patina::Telemetry`) beside the standard feedback | Six live readouts need about eighteen values a frame and a scope; the shared five-value frame stays as it is for every other module |
| 2026-10-25 | Vesper's send, duck and line ends are keyed by what the Listener hears, not by level | A level key ducks a quiet held note less than a loud one and ducks for a breath; keyed by "singing or not" the tail behaves the same at any level, a breath leaves it alone, and a consonant can be kept out of the send while a vowel of the same level goes in |
| 2026-10-25 | Vesper runs one network per space and lets the old one ring out after a change | A space is a tuning (line lengths), and changing a network's tuning means allocating; three prepared networks switch on the audio thread, and the old tail decays naturally instead of being cut by a fade. Only a network with input or energy runs, so the cost is one network most of the time |
| 2026-10-25 | Vesper decides from the past alone in its first form, so the first milliseconds of an "s" reach the reverb | The Listener needs a few milliseconds to hear a consonant; without latency the send cannot be down before it starts. Clarity still keeps an "s" about 12 dB or more lower in the reverb, and the planned Short lookahead (30 ms, opt-in) closes the gap for mixing |
| 2026-10-25 | Buttons, segments and pills centre their labels by their letters, not the font's line box | Centring ascent plus descent left every label 1-2 px low, the descent being empty for most labels; a word's weight is between its x-height and its capitals, so that is what is centred, and a label of capitals alone by its capitals |
| 2026-10-25 | Vesper's dusk sky is still; only the display, the star, the lights and each new star move | The plan had the whole sky brighten with the tail, but a face may not repaint whole while playing (ui-performance.md); the afterglow that moves is in the Evensong display, where it means something, and the evening star glows with the voice |
| 2026-10-25 | Vesper's face has no preset bar of its own | The card's header shows the effect's presets for every built-in; a second bar in the face would be the same control twice |
| 2026-10-25 | Vesper's display shows the audio as it comes out, after the lookahead | The telemetry is gathered where the delayed audio is processed, so a line-end star sits where the line is heard ending, whatever the lookahead |
| 2026-10-25 | Vesper's wordmark is set in the display serif's italic | The approved design is Newsreader italic, the brand's voice for something sung; the italic cut is bundled beside the upright (same licence), and the face falls back to the upright if the file is missing |
| 2026-10-25 | Vesper's presets are held to their character by measurement | A preset is a promise ("Throws Only"), and a change to the DSP can quietly break it; a test plays sung lines through each and checks the reverb's level under the singing and in the gaps, the decay, Swell and the headroom against what its name says |
| 2026-10-25 | Vesper's Lookahead is an ordinary parameter whose change re-solves the graph | The engine already compiles the graph again when an insert's latency changes (the limiter's lookahead does it), so an automated change costs a recompile, not a special case; Off stays the default so tracking never waits on it |
| 2026-10-25 | Vesper's frames are applied 6 ms before the audio they describe when the lookahead allows | The Listener hears a sound a few milliseconds after it starts, so a frame applied at its own moment leaves the start of every "s" in the send; with that lead Short keeps an "s" more than 20 dB out of the reverb |
| 2026-10-25 | Swell feeds the reverb the line still to come, not a reversed copy | The lookahead already holds the next half second of the vocal, so sending it early, rising, builds the tail into the first word without bouncing or reversing audio, and it follows whatever is sung |
| 2026-10-25 | The Editor panel's generic card adds columns when its height runs out | Its height is the dock's, so a long parameter list ran past the card's edge; widening keeps every control reachable without a scroll inside a card, as the rendered faces narrow and widen with the height |
| 2026-10-23 | Built-in effect presets are written and saved by parameter name, not position | A preset then survives parameters being added or reordered: a missing one takes its default, an unknown one is dropped. The factory lists name parameters the same way and the tests fail on a name that does not resolve |
| 2026-10-23 | Built-in effect presets sit in the card's and window's header, one bar for every effect | Presets are found in the same place on every effect, whatever its face; a face with its own control (Patina) shares the one list, so the two can never disagree |
| 2026-10-23 | Bloom's display is a polar spectrogram, time round and pitch outward, with Freeze at its centre | A reverb's tail is the whole point of Bloom; drawn as a flower that opens and fades it reads at a glance as something that grows and decays, where a scrolling spectrogram read as a utility. Freezing at the heart puts the defining control where the tail is |
| 2026-10-23 | Patina's card is a hardware face (a worn rack unit) in its own `hardware` token group, with generated textures loaded from `assets/patina` | Ageing sound is Patina's whole character, and a worn face says so at a glance, as the instruments' faces do. The panel stays fully worn at every Age: a face that changed with a knob drew the eye away from the readouts. The group keeps the rule that colours are tokens without bending the house palette; the images load at run time like the splash photograph and fall back to flat tokens, so the tests and a missing file never break the card |
| 2026-10-24 | UI performance is tested in three layers: counted work budgets in every `ctest`, timed paint budgets in Release builds only, frame benchmarks against a per-machine baseline | Timings on shared CI machines vary from run to run, so a timed gate there either flakes or is too loose to catch anything; counting what an interaction repaints and the words it sets is exact on any machine and catches the regressions that matter (a hover repainting a whole face). Paint times and real frames still need checking, so they run where they mean something: a Release build on the developer's machine, compared with that machine's own baseline |
| 2026-10-24 | A rendered face sets only the words in the area being repainted | A face prints 100 to 150 words, each measured by its glyphs' outlines; a hover or a live window repainting the whole set cost a full repaint (5 ms or more) for a few pixels, which dropped the frame rate under the mouse. Culling by the clip keeps a small repaint under a millisecond and needs nothing from the faces |
| 2026-10-24 | Patina's face is rebuilt from rendered parts, six stage modules with every control showing (replacing generated textures and a tabbed control row) | Beside Corona and the tape echo, a face of app controls on a photo texture read as a skin, and the row that swapped to the selected stage hid most of the unit and left gaps. Rendered plates, knobs and buttons give it the same material weight as the others; showing every control turns the six stages into a chain you can read at a glance, at the cost of a taller face (1160 x 680, so every small knob's name and value have room under its scale). Wear, with no type, puts its Dropouts and Skew where the selector would be, so the modules keep one set of rows |
| 2026-10-25 | Orbit's face is lit as a dim mastering room, its words printed over the renders | The mood is the machine's character, as the console is the tape echo's; printed words stay sharp and legible in the shadows where rendered lettering went dark. A lit key draws its patch of a second render with every key lit, so its glow on the panel is exact. |
| 2026-10-25 | Orbit's reels turn as 30 rendered frames over 120°, coasting to rest | Under a spotlight the reels' light cannot be parted from their turning (the windows show the pack and throw shadows), so a turning layer would turn the light with it. A three-windowed reel repeats every 120°; the nearest two frames are blended, and at rest the still render shows the reel sharp, so the frames are kept at the drawn size (about 20 MB decoded). |
| 2026-10-23 | The tape echo's card is a hardware face built from 3D renders (Blender, `scripts/render/tapeecho`), drawn at 1160 x 600 and scaled to fit its body | A tape echo's character is the machine, and drawn or generated parts never shared a light or a perspective; renders of every part under one top light and one room do. A face that keeps its proportions reads as one object at any size; laying it out again for each height would be a second design. The card narrows with the dock, and the plugin window shows it 1:1 |
| 2026-10-23 | On the tape echo's face, what turns is its own layer, and a lamp's light is a layer laid over the base | A rendered knob or roller turned whole would turn its highlights and shadow with it. Light rendered alone, as colour with alpha, makes a neon's brightness its opacity with its spill included, without blend modes JUCE lacks |
| 2026-10-23 | The tape echo's SYNC is a lever, and while it is on REPEAT RATE steps through the note values | A console has no menu; one knob for the motor whichever way it is set keeps the rate in one place, and the lever remembers the last note value |
| 2026-10-23 | The tape echo's levels show as a neon on each head and a VU for the record level, not as numbers | The old display's echo train reads at a glance as light travelling across the heads; the delay time is the REPEAT RATE knob's value and the active heads are HEADS's |
| 2026-10-23 | The exciter normalises its band before the drive and adds only what the curve adds | A fixed drive excites loud passages into grit and quiet ones not at all, and a saturated copy of the band mixed back also compresses it. Normalising makes Drive the character alone and Amount a level against the band, at any input level; taking out the curve's linear part (its describing gain at the calibrated level) leaves only new harmonics, so the dry sound is untouched. |
| 2026-10-23 | The exciter oversamples only its harmonics, not the signal | Twice the rate (polyphase IIR) plus ADAA keeps the curves clean, and because the dry signal never passes through the oversampler the effect has no latency and no phase change on the source. |
| 2026-10-23 | The exciter's auto gain is on by default and matches K-weighted loudness, only downwards | An exciter mostly adds upper harmonics, which sound louder than their RMS; "louder sounds better" makes an unmatched A/B dishonest. K-weighting counts the added highs as the ear does. |
| 2026-10-23 | The exciter's stereo adds a decorrelated copy to one side and subtracts it from the other | The mono sum is then exactly unchanged whatever the Width, so the effect cannot collapse or comb in mono. |
| 2026-10-23 | The exciter's display shows what is added as its own tap | Subtracting a before spectrum from an after one is noisy and cannot show harmonics under the input's level; tapping the added signal shows them exactly. |
| 2026-10-23 | Bloom's shimmer shifts inside each delay line, at constant power, turning at most 40° a pass | Two extra reads of the line it already has, so it costs no extra memory, and the network's mixing keeps the loop's gain at the decay's. A full crossfade emptied the original pitch upward in a few passes; 40° lets the tail climb over seconds. |
| 2026-10-23 | Bloom's shimmer path high-passed at 60 Hz, what is written low-passed below 0.4 fs / ratio | The lowest frequencies leave the two grain heads in phase (a gain above one) and shifting never moves them on, so they grew without end; content above fs / (2 × ratio) folds back down when shifted up and piled up at the top. |
| 2026-10-23 | Bloom's level held by a governor on the network's energy, not a saturator in the loop | A gain on the loop is linear and smooth: nothing to alias and no clipping to hear; it only acts when a setting (a minute's decay, full shimmer, a loud held input) would build past the ceiling. |
| 2026-10-23 | Bloom's damping and low cut are shelves whose depth follows the decay gain | The highs (and lows) decay a fixed four times faster at every decay, so a minute-long or frozen tail is not dulled to a hum in two seconds, as a fixed low-pass in the loop would. |
| 2026-10-23 | Bloom keeps its network running while bypassed | A reverb's state is its tail: bypass and back brings in a current tail (and a frozen tail stays held), at the cost of the processing while bypassed (none in silence). |
| 2026-10-23 | Bloom's swell is a cloud of taps on the input, not an envelope on the output | Each hit swells on its own, also inside a busy passage; an envelope opens once and stays open. No latency, unlike a true reverse. |
| 2026-10-23 | The tape echo models tape positions, not a variable delay line: each recorded sample keeps the tape position it was written at, and heads read by position | A variable delay bends each head's pitch differently, by head distance × the rate of change. On tape, every head reads the same moving tape, so a speed change bends all echoes alike by speed now ÷ speed then. Storing the positions gives that exactly, for one double per sample. |
| 2026-10-23 | All the tape echo's tone, saturation and wear sit on the record path, not on playback | Every repeat is recorded again, so it passes them once more: "more with each pass" falls out without a filter per head. A dropout written on the tape travels round the loop like a real worn spot. |
| 2026-10-23 | The tape echo's feedback is the active heads' mean | 100% is then the edge of oscillation in every head mode, and the card's loop gain (feedback × the loop filters' peak) means the same thing whichever heads are on. |
| 2026-10-23 | The tape echo's hiss follows what is on the tape | Constant hiss would hiss over every silent track. Tied to the tape's envelope (1.5 s release) it is heard under the echoes and fades with them, which is what makes it read as tape. |
| 2026-10-23 | The tape echo keeps running while bypassed | Switching it back on then brings in echoes of what just played, rather than resuming echoes of whatever played before it was bypassed. |
| 2026-10-24 | Corona reports no latency: IIR half-bands for the oversampling and a convolver whose first partition runs directly | It is played through while tracking, where every millisecond is felt. Linear-phase oversampling or a block convolver would add a buffer or more; minimum-phase half-bands add a few samples of group delay that no one hears, and the direct head makes the convolution exact with nothing to wait for. |
| 2026-10-24 | Corona's cabinet is a model that builds a response, not shipped impulse responses | Captured responses of real cabinets are someone's recordings and cannot be shipped freely; a model also lets a mic move continuously across the cone and back from it, and two mics comb by their real time of flight. Users with responses they own load them as a file. |
| 2026-10-24 | Corona's triode stages are static curves solved offline from Koren's equations, not a circuit solved per sample | A wave digital model of every stage costs several times the CPU for a difference heard mostly in extreme settings; a curve on the stage's real load line, with grid current and the bias shift added, keeps the stage's gain, asymmetry and breakup and leaves room for oversampling. |
| 2026-10-24 | Corona's tone stack is found by a nodal solve of the circuit, not from Yeh's published polynomial | The published coefficients, transcribed, missed the circuit by up to 6%; determinants of the circuit's own nodal matrix, interpolated on a circle, are exact for any component values and are checked against a direct solve in the tests. |
| 2026-10-24 | Corona's cabinet is rebuilt on one shared background thread that polls, not by the audio thread or a thread per amp | Building takes milliseconds, too long for a callback; automation moves the parameters on the audio thread, so the controller thread cannot be told either. A poll every 15 ms finds any change however it was made, and one thread serves every amp. The audio thread only reads the published kernel. |
| 2026-10-24 | Corona's face has two pages, the amp and its cabinet, with the strip along the foot on both | Twenty-odd cabinet controls and a baffle to drag mics on do not fit beside a full amp panel at a legible size. An amp's grille comes off to show its speakers, so a second page is a natural place for them; the input, gate, output, footswitch and page keys stay reachable from both. |
| 2026-10-24 | Rendered parts are drawn from copies shrunk to the pixels they cover, and a face's printed words are drawn outside its cached layer | Drawing a 2x render at a third of its size in one bilinear step aliased the chrome's highlights into sparkle; halving in steps before drawing keeps them clean. Words drawn into the cache came from the software renderer and were resampled with the image; drawn live they are set by the window's renderer at their real size. |
| 2026-10-24 | Corona's mics on the baffle are markers, not renders | A render of a mic seen from the speaker read wrongly at the size and angle it is drawn; a ring sized by distance with the type's glyph shows where each mic is and what it is at a glance. |
| 2026-10-24 | Rendered faces have a compact form below 65% of their size: small print goes and names grow | In the Editor dock a face shows at about 40%, where values and scale numbers were 4-5 px tall and unreadable on any renderer. The knobs' pointers show their settings; a value is one hover away, shown in the name's place. A second layout per face would be two designs to keep. |
| 2026-10-24 | Face text is set at its device size on a whole-pixel baseline, not drawn through the face's scale | Under a scaled transform JUCE's Direct2D path draws glyphs as scaled outlines with no grid fitting, and the face's own centring could land on half a pixel. ClearType would need patching JUCE's renderer and breaks over layers, so it was not taken. |
| 2026-10-24 | A two-way lever flips on a click anywhere on it | Hitting the nut, and above or below its middle, was a target players missed; a two-way switch has only one other position to go to. A three-way lever keeps the side-of-the-middle rule, as it must choose a direction. |
| 2026-10-24 | Corona's look is its own: oxblood tolex, a champagne plate, our cloth and badge | It is modelled on a famous amp but must not pass for it: no logo, no name, no black or silver panel; the sound is the model, the face is Northlight's. |
| 2026-10-23 | The widener scales only the side, per band, with the mid through the crossovers' allpasses | LR4 low and high outputs are in phase with the allpass that is their sum, so the side bands and the mid share one phase: at 100% the sound is unchanged, and the mono sum is the mid at any width. |
| 2026-10-23 | Spread adds a copy of the mid to the side only (Diffuse: an allpass network; Haas: a delay) | It cancels exactly in the mono sum, so widening a mono source can never comb-filter it in mono; the allpass network leans each frequency a different way instead of a Haas delay's regular comb. |
| 2026-10-23 | The widener's level compensation scales mid and side together | Keeping the stereo power steady as the width changes needs a gain on both; the mono sum keeps its shape and moves by at most -6/+3 dB. |
| 2026-10-23 | The widener's guard narrows to no less than 25% of the side | Past that the image is a polarity problem; narrowing further would make the sound vanish, so the meter shows it red instead. |
| 2026-10-23 | The widener's two taps carry its output's left and right channels | The vectorscope and the width spectrum need both channels; the taps were the existing real-time-safe path, so `ProcessorFeedback` did not change. |

### MIDI

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | Note-offs come from each track's own continuity check, not transport commands | Comparing each span's start with where the last ended catches every locate, wrap and stop in one place. |
| 2026-10-19 | MIDI events are a fixed list per track per span, sized at compile | Built in the track's render job, allocation-free and in time order. |
| 2026-10-19 | Recorded MIDI is placed by the output-side latency only | The player plays to what they hear; subtracting input latency as for audio would place notes early. |
| 2026-10-19 | MIDI devices are identified by name | The name is what the user recognises and what a project carries between machines. Devices sharing a name are all opened. |
| 2026-10-19 | A built-in synth ships with the engine | A MIDI track must make a sound without third-party instruments, for users and for offline tests of the whole path. |
| 2026-10-19 | Trimming a MIDI clip keeps its notes in place on the timeline | Matches audio clips and makes a trim undoable by trimming back. |

### Files and settings

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | Audio settings are a JUCE-free value type stored as flat key/value pairs | Testable without JUCE, with a simple on-disk format. |
| 2026-10-20 | Parameters are saved with stable keys and reconciled on load | Saving by position shifts later values whenever a processor gains a parameter. An upgrade chain replaces refusing older files. |
| 2026-10-20 | Missing media is detected once per project change, not per paint | A file check per clip per frame would stall painting on a slow volume. |
| 2026-10-19 | First run is detected by the settings file's absence | No flag can go stale, and the first-run sheet never shows again once a setting is saved. |
| 2026-10-22 | A project opens in steps: reading and decoding on a thread, plugins one per message-loop step | Plugin creation must stay on the message thread (VST3 and CLAP require it), and a plugin can take most of a second, so the window paints the next plugin's name before making it. Swapping the project in only when the plugins start keeps the current one untouched, and cancellable, through the slow file work. |

### Interface

| Date | Decision | Why |
|---|---|---|
| 2026-10-19 | `JUCE_MODAL_LOOPS_PERMITTED=0` | Async dialogs only, so the message thread never re-enters during a modal loop, a classic source of host and plugin deadlocks. |
| 2026-10-19 | Theme tokens load from `docs/design/tokens.json`, embedded at build time and also shipped beside the app (replaced a hard-coded C++ struct) | The app and tests never depend on finding a file, and a designer can try a change without a rebuild. A user override holds only changed keys, so new defaults still reach them. |
| 2026-10-19 | Glows are rendered once per size and colour into images | A per-frame blur is the one expensive thing in the tactile layer. Reduce-motion drops glows entirely. |
| 2026-10-19 | Edits are previewed in the view and committed as command groups | A drag issues no commands until release, which becomes one undo step. The model never sees a half-finished edit. |
| 2026-10-20 | Selection has one owner that notifies one listener | Views caching their own selection drifted out of step. |
| 2026-10-20 | The mixer's sections are real slots and rows, not menus | Signal flow must be visible on the strip; menus keep only what has no control of its own. |
| 2026-10-19 | Panels are owned by one of three hosts and never destroyed on close | Panels keep their state across moves; closing a floating panel returns it to its default host, so none can be lost. |
| 2026-10-22 | Late callbacks are timed against a due time that snaps to early arrivals and follows late ones slowly | Callbacks can be delayed but never early, so the earliest arrivals mark the schedule; following late ones slowly absorbs clock drift without hiding a stall. Splits and catch-ups (a block right after the previous one) are not judged. |
| 2026-10-22 | The output tap finds clicks with a linear-prediction error test, not a slope or level threshold | Slope thresholds fire on every drum hit; a sample the last 16 do not predict is a discontinuity in any material. |
| 2026-10-22 | Driver dropouts show "not reported" when the driver cannot count them | Most ASIO drivers cannot; a 0 there told users nothing was wrong when nothing was being measured. |
| 2026-10-22 | All UI meets a design bar: every element and state designed, nothing at a toolkit default | Automated checks catch literal colours and contrast, not a screen that looks unconsidered. Reviewing captures against a written list holds visual quality to the same standard as correctness. |
| 2026-10-24 | Font size tokens are em sizes, and text boxes take their height from the face | A JUCE font "height" is ascent plus descent, so every token drew about a sixth smaller than its number and smaller than the same size in the design files. Boxes sized "size + 4" were built around the smaller text; `Theme::lineHeight` measures the face, so a box fits whatever the size. Hardware legends stay JUCE heights because their art was drawn around them. |
| 2026-10-22 | The transport readout spaces its text, not fixed boxes, and draws every field on one baseline | Fixed boxes with centred text left the gaps to chance (51, 40 and 24 px) and four alignments; boxes that hug the text keep the gaps equal at any value. The well grows by a figure at bar 10 and 100, which happens rarely and moves the flanks a few pixels. |
| 2026-10-24 | The guitar pedals' footswitch switches the insert's bypass; the tuner's mutes its output | A pedal's footswitch is how it is switched on and off, and the insert's bypass already is that (undo, the header's power, the dimmed card), so a separate "on" parameter would give two switches for one thing. A tuner pedal is different: it reads whether on or not and its switch silences the signal, so Polaris has a Mute parameter, and bypassing it switches the tuner off. |
| 2026-10-24 | The guitar pedals reuse Corona's footswitch button, jewel and bat toggle, and share one card | One lighting and one hardware family across the guitar group, five fewer sets of renders, and one card to keep in step; only the enclosures (one per finish) and the knob are new. |
| 2026-10-24 | Polaris hides readings with a clarity under 0.8 | YIN finds a period in a chord too, often an octave or two below any string, and a tuner that names it misleads; a single string reads well above 0.8, a chord below it, so the display shows a dash for a chord as a hardware tuner does. |
| 2026-10-25 | Automation lanes are rows under their track, one per parameter, not drawn over the track's row | Drawn over the row, the parameter chips covered bar 1 (a point at the song's start could not be clicked), only one parameter showed at a time and the clips dimmed and stopped taking clicks. As rows, every lane shows at once at its own height, and collapse and hide keep the view tidy without removing automation. The rows join the row's block the way take lanes do, so every row lookup stays per channel. The mode stays per channel (on A), as the model has it. |
| 2026-10-25 | The arrange view's erase tool is key 4, after select, range and pencil | It is 4 in the piano roll, so one key erases in both; split, glue and mute follow as 5 to 7. |
| 2026-10-25 | The split tool cuts every track with Shift; Alt takes it off the grid | Alt overrides the snap everywhere (interaction.md 10.2), and Shift already means extending what an action covers. |
| 2026-10-25 | The glue tool joins audio only where the next clip continues the same recording | Joining across a gap or two files would need a render. A clip that cannot join says why instead of doing something else. MIDI clips have no media, so they join across any gap. |
| 2026-10-25 | Note names call middle C (MIDI 60) C3 everywhere, the tuner included | The piano roll, Pulsar and the pitch editor already did, as most DAWs and the Pulsar pad map do; the Sampler and the Polaris tuner said C4, so one note had two names. One helper (`core::noteName`) now names every note, so A 440 reads A3 on the tuner too. |
| 2026-10-25 | A project is modified when its undo history is away from the save point, or when something changed outside the history | A flag set on every edit could never go clean: undoing back to what was saved still asked to save. The history knows where the save was; what it cannot see (a restored autosave, a preset loaded in a plugin's own window, which VST3 reports through setDirty and CLAP through mark_dirty) sets a separate flag until the next save. |
| 2026-10-25 | Pitch edits on a stretched or transposed clip are refused, with a note, rather than rendered through the stretch | The stretch renders from the media file in the background, so the edits were silently not heard. Playing both would mean re-rendering the stretch from the pitch-edited audio after every edit; until that is worth its cost, pitch mode says why it cannot edit such a clip and takes no edits. |
| 2026-10-25 | A command that cannot run returns false from apply or revert instead of throwing | A stale command (its track removed by an undo) is an expected case, not an exceptional one, and AGENTS.md asks for failures to be returned. Each command looks its targets up before changing anything, so false means nothing changed; the stack and the session drop it and log its name. A file entry of the wrong type (a note, a point, a parameter value) is likewise skipped on load instead of failing the whole file; a top-level field of the wrong type still refuses it. |
| 2026-10-25 | The undo history keeps at most 1000 steps and about 256 MB, dropping the oldest | It was unbounded, and some steps copy a lot (removing a track keeps the whole track, a pitch edit two whole vocal edits, a tempo edit every clip's position). A count alone does not bound memory and a size alone lets thousands of tiny steps pile up, so both apply; each command estimates its own size from what it copied. The newest step is always kept, however large. When the step the file was saved after is dropped, undo can no longer get back to the saved state, so the project stays modified until the next save. |
| 2026-10-25 | Every timeline view maps time to pixels through one viewport, rounding down, and zooms by one smooth wheel factor | The arrange view, the piano roll, the audio editor and the arrange view's lanes each had their own mapping (truncating, flooring, rounding to nearest, the tempo track deriving the zoom from two lookups), so one sample could land in neighbouring columns in two views. `ui::TimelineViewport` holds the one rule: a sample's column is its exact x rounded down and a column starts at the first sample that maps into it, so the waveform columns, the grid and the mouse agree. The editors' wheel zoom stepped by 0.8 or 1.25 whatever the wheel's movement while the arrange view's was smooth; linked views now zoom alike, a notch still about a fifth. |
| 2026-10-26 | Region from the loop and split at the selection are Alt+M and Alt+S; Redo shows Ctrl+Y | Shift+M and Shift+S mute and solo the selected track, so the window remapped Alt+M and Alt+S onto the arrange view's Shift bindings and the spec, the page and the code each said something else. | 2026-10-26 | One keyboard registry with contexts, rebindable on the Shortcuts page; fixed families stay fixed | The page, the handlers, the menus and the user guide had drifted apart. With every key in one registry (id, name, section, context, defaults) everything reads the current binding, so a rebinding cannot leave a stale label. A key may be bound once per context; a view's key collides with a global one because the view takes it first while focused. The tools' number keys and the arrows work as sets (the index is the tool), so they are listed but not rebindable. Bindings save as the changed commands only, so new defaults reach users who never rebound them. |
| 2026-10-26 | Arm is Shift+R; Ctrl+R is not bound | The spec gave both. Shift+R matches Shift+M and Shift+S for the selected track's mute and solo, and R alone records. |
| 2026-10-26 | G and E no longer toggle snap and ripple in the arrange view | They duplicated N and Shift+N, undocumented, and took two letters. The piano roll keeps G for its own snap, which is separate from the arrange view's. |
| 2026-10-26 | Pause (Shift+Space, and Play while playing) keeps the position; Stop returns to where playback started, on by default | Pro Tools, Logic and Cubase return on stop by default, so a take can be played again with one key; Pause is the way to stop and stay.
